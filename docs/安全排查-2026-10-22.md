# 安全排查（2026-10-22）

范围：当前 v1.0.3 工作区源代码、锁定依赖、部署流程、正式首页响应头。采用小型合成文件和独立的内存数据库验证，不向正式网站导入测试文件，不读取或改写用户凭证。本轮仅排查；没有修改产品代码或发布。

结论：本次未确认远程代码执行、凭证外传或可利用的页面脚本注入；发现文件处理的资源限制缺口和需要明确的隐私边界。此结论不等于不存在未知漏洞，也不代表已审计浏览器、WASM 引擎或 GitHub 基础设施。

## 1. 中风险：ZIP 解压前的大小检查可被伪造元数据绕过（已复现）

位置：`src/storage.js:176`、`:260`、`:263`。

`checkArchiveLimits` 检查中央目录声明的 `uncompressedSize`，之后 `checkCRC32: true` 会同时解压归档中的所有条目。JSZip 在条目解压结束时才检查实际长度与声明是否一致；CRC 校验也不是流量限制。未支持的额外文件则到 `:298` 才被拒绝。

使用 DEFLATE 压缩的 1 MiB 重复字节与一个空记录 JSON，将额外条目的声明长度改为 1 字节，观测解压流：

```text
ZIP bytes: 1256
declared extra bytes: 1
actual bytes inflated before rejection: 1048578
rejection: Bug : uncompressed data size mismatch
```

实际影响：需要用户选择恶意备份；可能消耗大量 CPU/内存、导致标签页失去响应。该复现没有造成系统内存耗尽，也不证明远程入侵。异常发生于写事务之前，不能据此断言现有数据库被覆盖。

建议：逐条、有界解压，在每个输出块检查实际字节上限并中断；避免先对整个包执行并行 CRC 解压。先拒绝非法路径和不支持的条目，再处理内容。在可终止 Worker 中处理归档并设置超时；CRC 与 SHA-256 校验仍须保留。

## 2. 低风险：恢复入口只验证照片路径和摘要，没有验证图片内容（已复现）

位置：`src/storage.js:153`、`:280`；显示入口 `src/app.js:412`。

把不含脚本的 HTML 文本放入合法的 `photos/{uuid}.png` 路径，配上该文本的正确 SHA-256 和合法记录，`restoreZIP` 成功返回 1；存储 Blob 的 MIME 为空。这证明非图片能够进入照片库。摘要只能验证字节一致性，不能证明文件可信或来自本程序。

目前未在浏览器中证实脚本执行或 CSP 绕过，不能把这项认定为已确认 XSS。照片通过 Blob URL 显示并能在新标签页打开，因此应收紧边界，而不是依赖扩展名和浏览器嗅探。

建议：导入、恢复共用内容类型验证，拒绝 HTML/SVG 等主动内容，检查受支持的真实栅格格式，设置准确 MIME。原图放大使用受控图片查看器。兼容既有真实备份，并保留原图字节与摘要的一致性。

## 3. 资源风险：图片在缩小前已完成原尺寸解码（代码确认，未制造内存耗尽）

位置：`src/app.js:583`、`src/ocr.js:95`。

30 MB 文件体积限制不能限制像素数量；`createImageBitmap` / `Image` 先解码，随后才缩小到最长边 3000 像素。高压缩率、超大尺寸图片仍可能占用大量内存。现有 OCR Worker 的请求超时没有覆盖前面的图片解码。

建议：在解码前读取支持格式的尺寸头，限制总像素和边长；采用有资源限制的解码路径、可终止处理和批量取消机制。解码后尺寸检查只能补充防护，不能替代解码前限制。本轮没有使用巨大图片压测浏览器。

## 4. 隐私边界（当前设计，不等于已泄露）

- 备份 ZIP 没有加密，`receipts.json` 与原图可被普通解压工具读取。不要把备份当作加密保险箱；如需加密，应采用经验证的口令加密方案并设计好口令丢失提示。
- `remove` 只删除记录，原照片仍留在 IndexedDB。此行为是此前保留原图的设计。本轮没有改动。可另加明确的“彻底清理未引用照片”功能，并说明其不可恢复性；日常删除与彻底清理需要区分。
- 网站没有登录控制，其他人知道地址就能打开程序。凭证仍各自保存在浏览器，公开页面不意味着他人能直接读取你的本地凭证。
- `https://pangtanpurpleu.github.io/其他项目/` 与本项目具有相同源。在同一浏览器存储环境中，该主机其他项目的脚本也处于 IndexedDB 的同一权限边界；不同路径不隔离本地数据库。仅当同源其他项目执行恶意脚本时才构成此风险，本轮未发现这类项目或入侵证据。需要隔离时使用独立主机名；迁移前先备份，域名变化不会自动迁移旧数据。

## 已检查的防护

- 应用代码中未发现将凭证照片、识别文字上传第三方的网络路径；模型与运行文件走同源请求。此项是代码检查，没有对每个第三方 WASM 指令做完整审计。
- 页面主要动态内容使用 HTML 转义；Excel 文字写为转义后的 `inlineStr`，没有把识别文字拼成公式。未发现直接可利用的这类注入路径。
- 备份已有 CRC、照片 SHA-256、路径/条目数校验，以及写入前校验、恢复原子事务和并发变更保护；上述 ZIP 问题不意味着这些保护全部失效。
- GitHub Actions 的 action 使用固定提交，构建与部署权限分离；依赖版本固定。
- 对 81 个受 Git 跟踪文件中的常见文本文件扫描私钥、GitHub token、AWS access key 和常见 API key 特征，没有命中。未扫描 Git 全历史、GitHub 账户设置或部署 Secrets，不据此承诺不存在其他形式的敏感信息。
- npm 官方 bulk advisory 接口对锁文件中的 38 个非平台重复依赖包版本返回 HTTP 200、空漏洞结果 `{}`。这是当日已收录公告查询结果，不能排除未收录漏洞。
- 正式首页返回 HTTP 200、`server: GitHub.com`，有 HSTS。CSP 通过 HTML meta 提供，未提供响应头级 CSP、X-Frame-Options、nosniff 或 Referrer-Policy。嵌入限制应通过 `frame-ancestors` 响应头实现；不能把它加进 meta 就声称已防点击劫持。未验证点击劫持利用。
- 现有测试：131/131 通过。最初沙箱限制本地预览端口，随后允许本机回环服务的完整运行通过。

## 后续优先级

1. 有界解压与可取消处理。
2. 图片真实格式、MIME 和像素上限。
3. 明确删除/备份隐私语义；按实际需要增加清理或加密。
4. 若同主机还要托管其他程序，考虑独立主机名与响应头控制。迁移涉及旧数据导出导入，不应直接替换域名。

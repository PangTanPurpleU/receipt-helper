## 结论

目前的浏览器本地架构适合这个工具：OCR 放在 Worker，图片与凭证存入 IndexedDB，按平台分别解析，下载资源带 SHA-256 校验，查重使用候选索引，完整凭证仅一轮识别，补扫次数有上限。现有自动测试基线为 99 项，说明项目已有良好防回归基础。

本轮重点修复金额完整性、补扫污染、弱证据误判、手工录入和可访问性。没有更换 OCR 模型或大规模重写界面。最终 112 项测试通过，构建成功，并完成真实浏览器合成样本 OCR、修改保存与 Excel 下载验收。

## 已修复问题

| 优先级 | 问题与原行为 | 修复 |
| --- | --- | --- |
| 高 | 电子凭证的小写金额将所有逗号改成小数点，并只匹配末尾数字；`1,234.56` 会成为 `234.56`，`12.345` 也可能被截取为 `345.00` | 新增 money.js，校验完整字段；正确识别千位分隔、一位/两位小数、全角数字及货币前后缀。电子凭证保留受限的逗号/顿号小数修复。乱码不再截取尾部 |
| 高 | 通用金额直接删除逗号，`12,34` 会无依据地变为 `1234.00` | 只有合法三位分组才删除逗号；通用凭证遇到歧义保持缺失、触发核对 |
| 高 | 金额大小写不一致只有警告，不触发补扫；`12` 与 `12.00` 还会被误认为冲突 | 以分为单位比较；真正冲突触发原有有界补扫，仅当补扫小写与原大写一致时修复有效但冲突的小写值 |
| 高 | 补扫读到另一个完整单号时，仍可能将其收款方等字段填入原交易 | 两个完整有效单号冲突时拒绝合并，保留原记录及待核对状态 |
| 高 | 金额、时间与脱敏姓名相同时，弱条件仍可能判重 | 带星号、遮蔽圆点或省略号的姓名不再参与此弱条件；相同照片、完整单号仍可作为依据 |
| 中 | 两个完整单号不同，但凭证编号相同时仍判重，与项目已有冲突处理原则不一致 | 将凭证编号纳入完整单号冲突保护；同照片的独立依据保留 |
| 中 | 粘贴全角金额、货币符号、带空格长单号后未规范化 | 保存时仅规范结构化字段；保持商户单号中的合法字母，如 `13L`，不全局替换文字 |
| 中 | 交付包中没有 .git，原打包脚本直接失败 | 支持从允许的目录集合打包；缺 Git 时 sourceCommit 明确为 null |
| 中 | Finder 启动脚本找不到已安装但未进入 PATH 的 Node | 检查常见 Node 路径及本机 Codex 已有运行库后启动 |

金额模糊但存在可解析的大写时，仍沿用原有大写回退规则。金额冲突无法取得一致证据时保留警告，不强行选择新值。批量识别缓存与最大补扫次数保持原设计。

### 收尾阶段追加修复

- 保存时给记录分配修订号，手工修改及重新识别在写入前检查原修订号，防止覆盖其他页面的新数据或重新创建已删除记录；恢复备份也生成新修订号。
- 页面通过 BroadcastChannel 接收其他页面的保存、删除和恢复通知，刷新列表而不替换正在编辑的草稿。旧草稿提交时显示冲突提示。
- 备份记录和照片在同一个 IndexedDB 只读事务内读取，避免混用不同时间点的数据。
- 数据库同时打开请求共用连接；收到版本变更时关闭旧连接。
- 合计使用 BigInt 累加分位，显示不再经过 Number。超出 Excel 15 位精度边界的金额及合计导出为文本保真；普通金额继续保持数字和 SUM 公式。
- Service Worker 构建版本包含 HTML、JS、CSS、图标、manifest，避免仅改 HTML 时构建版本不变。
- 已将源码、工具、CSS 和 HTML 格式化，便于继续维护。fake-indexeddb 仅用于开发测试，不进入浏览器运行依赖。

## 后续值得继续优化的方向

1. **建立经用户授权的真实样本回归集。** 分别统计金额、单号、日期、收款方的精确匹配率、补扫率和手机耗时；在得到这些基线前，不应随意更换模型或宣称准确率提高。
2. **为字段保留来源与可信度。** 当前解析与合并主要依赖格式是否合法；格式正确的 OCR 错字仍可能通过。可以内部记录文本框位置、原文和模型分数，优先补扫低可信字段。需要用真实样本确定阈值，避免每张都多扫几轮。
3. **逐步拆分 app.js。** 本轮已格式化全部源码。若继续增加功能，可将列表、详情表单、导入控制器拆成独立模块；当前无需为了规模引入新的前端框架。
4. **保留照片占用的可见性。** 删除记录保留照片是当前明确设计，长期删除后仍可能占用空间。可另加容量展示与用户主动清理入口，不应静默改为删除照片。
5. **更完整的跨设备验收。** 本轮已验证真实浏览器双页面保存冲突、快照备份、390 px 宽度，但还需用 iPhone Safari 真机检查后台切换、缓存回收和手势。
6. **离线更新体验。** 本轮完善了 shell 版本覆盖，现有离线回退测试通过。进一步的整包原子切换可以作为后续版本策略设计，需要结合部署方式测试，不宜在没有线上环境时直接替换。

这些后续方向需要新的样本、设备或产品取舍，不属于本轮已实现的能力。网页本地存储仍依赖浏览器保留数据，建议维持现有备份操作。

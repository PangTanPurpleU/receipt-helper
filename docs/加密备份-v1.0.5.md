# 加密备份 v1.0.5

“备份当前凭证”现在要求设置并确认 12～128 字符的密码；支持显示密码核对。密码不写入数据库、Web Storage、缓存或日志。关闭弹窗会清空输入并移除弹窗。忘记密码无法找回，网站不保存密钥；不要使用容易猜到的短语或重复密码。

新下载文件是标准 WinZip AES-256 AE-2 ZIP。外层仅有一个加密的 `backup.zip` 条目，内层保存原有 `receipts.json` 和照片，避免明文暴露凭证文件名。总文件大小和外层通用条目名仍可见。可直接在本站恢复；用支持 ZIP AES 的解压工具打开时，输入密码后先取出内层 ZIP，再解压获取记录和照片。并非所有系统自带解压工具都支持 ZIP AES。

使用固定版本 `@zip.js/zip.js@2.24.0`，不自创加密算法或文件协议，不使用传统 ZipCrypto。AE-2 的认证校验用于检测密文损坏，原有照片 SHA-256、JSON/图片校验和有界解压继续生效。完整备份加解密在本地可超时终止的 Worker 内执行；库被打包到本地应用和恢复线程中，无第三方 CDN 或密码上传。

恢复兼容旧版未加密 ZIP 和本站新加密 ZIP。新备份输入原密码解密；已有当前凭证时，另外设置恢复前安全副本的新密码，自动下载的安全副本也加密。取消不生成下载。密码错误、损坏文件或并发变更均不会覆盖当前数据库。旧下载文件不会自动变为加密文件；如需保护旧备份，应重新导出加密版并自行管理旧文件。

验证记录：

- 加密条目头核对：AES vendor `AE`、AE-2、strength 3；每次导出使用新的随机盐，重复备份密文不同。
- 检查导出二进制不包含原照片路径、文件名、JSON 名称或识别原文。
- 使用 Node 原生 PBKDF2-HMAC-SHA1、AES 和 HMAC 独立验证并解密新库生成的 ZIP，也验证了实际浏览器下载文件；解密后的内层备份记录和照片可读取。
- 自动测试覆盖缺少/错误密码、密文篡改、中文和空格密码、正确往返、旧 ZIP、超限及并发恢复保护。
- 浏览器验证双密码不一致被拦截、加密下载、错误密码拒绝且原数据保留、安全副本同样加密。
- 停止本机 HTTP 服务后，刷新页面并成功解密恢复浏览器下载的加密备份，确认全程离线可用。
- 取消后密码弹窗和输入框已移除，现有凭证保留。开发与浏览器测试均使用合成凭证及测试密码，没有向正式网站写入测试凭证。

最终测试日志与弹窗截图见 `validation-v1.0.5/`。npm 官方漏洞接口对新依赖版本返回空公告结果（2026-10-22）；这不表示能排除未知漏洞。

# 查重小助手

网站入口：https://pangtanpurpleu.github.io/receipt-helper/

免费的浏览器本地凭证 OCR、查重与 Excel 导出工具，适配 iPhone Safari 和桌面浏览器。

照片、识别文字和凭证记录只保存在当前浏览器，不上传、不同步。PaddleOCR v6 tiny 是唯一识别模型，在浏览器 Worker 中免费运行。首次下载约 30 MB（含共用运行库），已有 tiny 资源可继续复用。完整下载后显示紧凑的绿色就绪状态栏；未下载时显示下载卡片。已下载资源支持离线识别，缓存被浏览器清理后需重新下载。

2026-10-14 用户在手机上使用 v6 tiny 测试 46 张照片，反馈均正确且速度快，因此移除 v5 mobile 和 v6 small。请继续核对金额和长单号。页面突出金额统计与凭证列表，筛选栏保留全部、重复、待核对。长按凭证进入多选并自动选中该张，随后点击切换选中状态；取消最后一张、取消全选或删除所选后退出多选。确认删除后只从网页列表永久移除识别记录，保留浏览器照片副本，手机相册原图不受影响。

## 功能

- 微信支付电子凭证、微信支付转账电子凭证、支付宝账单详情截图与微信账单截图识别、字段核对、重复依据展示。
- 筛选、长按多选与确认后仅删除凭证识别记录。
- Excel 导出按类型适配：电子凭证保留原五列；支付截图或混合列表增加凭证类型、商户显示名称、商家订单号和付款方式。共同核心为支付/交易时间、实付金额、收款方、订单/交易单号，订单按文本保存，重复标红。
- ZIP 本地备份、恢复及恢复前备份。
- 移动端布局、深色模式、减少动态效果适配、添加到主屏幕。

## 支付宝截图

识别“账单详情”中的实付金额、支付时间、收款方和支付宝订单号。收款方优先采用“收款方全称”，缺失时使用顶部显示名称，保留脱敏星号。头部金额的负号表示支出，列表按支付金额正数记录；不把订单原价、折扣、积分或乘车时间当成实付金额和支付时间。商家订单号显示为“商家可扫码退款或查询交易”时留空，不猜测条码下被隐藏的编号。不同平台的订单号分开比较，不能仅凭相同金额和脱敏姓名判重。

截图不要求付款方姓名和大写金额，四个核心字段完整时只运行一轮 OCR；缺字段时优先定位字段标签补扫，精确补扫失败后最多再做一次较大范围补扫。细节页按类型展示字段，保留商家显示名、全称、付款方式、商品说明等可用信息。首页优先显示商品说明，缺失时显示收款方。

2026-10-15 本地验收使用 22 张私人支付宝样本，四个核心字段共 88 项与人工核对一致；另加重复副本验证网页批量导入与 Excel 导出。样本和原始 OCR 结果不进入仓库，合成回归用例放在 `tools/alipay.test.mjs`。这是样本内验收，不是对所有截图的准确率保证。

## 微信账单截图

识别商户支付、扫码付款和个人转账三种结构。商户收款方优先使用商户全称，缺失时采用顶部名称；扫码付款和个人转账保留顶部可见的收款人。个人转账截图不套用转账电子凭证的收款方隐藏规则。首页优先显示商品内容，缺失时使用收款方；详情保留商户显示名、商户单号、支付方式、商品、转账说明和收款时间。

以顶部实付金额和明确的支付/转账时间录入；原价、优惠、收款时间、退款金额和退款时间分别保存。含退款的账单保留原支付金额并提示核对，首页合计不自动扣除退款。Excel 单独导出退款金额和退款时间，并保留商品、支付类型、收款时间、状态及优惠信息。条码旁明确可见的商户编号可以录入商户单号，绝不替代交易单号。

同平台、同种交易的完整交易/转账单号可在截图与电子凭证之间查重；支付宝与微信单号分开比较。两个完整单号不同的时候，不使用相同商户订单或金额时间等较弱证据判重。相同照片字节仍保留独立的重复依据。

2026-10-15 本地使用 20 张私人微信截图逐张实测，金额、时间、收款方、交易/转账单号共 80 项与人工核对一致。20 张均单轮识别；桌面本次识别耗时中位数约 0.90 秒，不包含模型初始化和图片解码，也不代表手机耗时。商品长文本仍可能有个别字符错误，应在详情对照原图修改。合成回归用例位于 `tools/wechat.test.mjs`；真实样本不进入仓库。

识别弹窗仅保留一个标题、张数、进度、文件名及本地处理说明，去除重复状态文字和停止按钮。日常优化以精度和单张耗时为主，暂不安排千张列表优化。2026-10-15 的 42 张完整识别对比、10 张补扫模拟与耗时边界见 `docs/RECOGNITION-2026-10-15.md`。

## 陌生类型凭证

已知微信、支付宝凭证继续使用专用解析器；其他版式自动进入通用识别，按字段标签与版面关系提取金额、日期、商户、流水号和商品摘要。实付不清楚或同级金额冲突时自动补扫，不取原价或合计充数。只有日期或分钟的凭证保留原精度，不编造秒数。

通用凭证不强制要求原图没有的付款人或单号。缺少关键字段时先扫描文字所在区域，仍缺失时至多再扫描一次完整图片。完整凭证只跑一轮。通用单号查重同时限定机构、商户、金额与精确交易时间；日期不完整时不以单号自动判重，相同照片仍可查重。首页、详情和 Excel 保留商品摘要和来源。

这是本地通用规则与自动补扫，不会在线训练模型。无法辨认或互相矛盾的内容仍需具体字段核对，但会保留已提取的内容和原文。验收记录见 `docs/ADAPTIVE-2026-10-15.md`。

## 开发与部署

使用 Node.js 24 和 pnpm 11.25.0，在本目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
```

仅发布构建生成的 `dist/`。模型位于 `assets/models/`，构建时会生成文件大小与 SHA-256 清单；第三方许可随网站一起输出。页面和模型路径均为相对路径，支持 GitHub Pages 项目子路径。

GitHub Actions 在推送 `main` 时自动构建、测试并发布 GitHub Pages。发布权限限定在部署任务，不需要保存个人访问令牌。此仓库不包含真实凭证、私人研究数据或登录配置。

维护约定：项目所有者已授权在修改完成、构建及相关验证通过后直接发布到上述网站，供手机查看验收。发布后应确认 GitHub Actions 部署成功和线上页面更新。

## 从旧网址迁移本地凭证

不同网址的浏览器存储互相独立。请在旧网站通过“更多操作”导出 ZIP 备份，保存到设备，再在新网站通过“恢复备份”导入。新网址需要单独下载识别模型；迁移网站不会自动复制旧网址的本地数据。
